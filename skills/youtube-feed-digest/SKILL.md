# YouTube 推荐流摘要

替用户刷一遍 YouTube，把推荐和订阅列成清单让他挑，再给挑中的写要点摘要。

这个 skill 存在的理由是省掉「打开 YouTube 然后刷了四十分钟」那一段。所以两件事必须做到：**清单要让人能在十秒内挑完**，**摘要要让人看完就知道这视频值不值得点开**。

## 流程

### 1. 拉清单

`$SKILL` = 本 skill 所在目录，加载时由 harness 注入。

```bash
"$SKILL/scripts/fetch_feed.py" --source both --limit 20 --min-duration 90
```

- `--source` 取 `rec`（首页推荐）、`subs`（订阅更新）或 `both`（默认）。用户说「今天推荐了什么」偏 `rec`，说「订阅更新」「关注的人发了什么」用 `subs`。
- `--min-duration 90` 把 Shorts 滤掉。用户没说要看 Shorts 就默认带上这个。
- `--limit` 是**每个源**的上限，不是总数。
- `--format json` 给你自己后续处理用；给用户看的是默认的表格。

登录态是从浏览器 cookie 借的，脚本不落盘任何凭证。默认读 Chrome，用 `--browser safari|firefox|edge|brave` 换。

失败时按退出码处理，别自己瞎猜内容：

| 退出码 | 意思 | 怎么办 |
|---|---|---|
| `0` | 正常 | 往下走 |
| `3` | cookie 读不到，或 YouTube 认为未登录 | 把脚本打印的排查步骤转给用户，常见原因是浏览器没登录、钥匙串授权被拒、用的不是默认 profile |
| `4` | 抓取失败 | 把 yt-dlp 的原话转给用户 |

### 2. 让用户挑

把表格原样给用户，然后问他要哪几个。**问完就停住等回复，不要自己替他挑。**

用户可能这么回：`1 3 7`、`1,3,7`、`前三个`、`所有 CCTV 的`、`那个讲强化学习的`。都要能对上号；对不上就把候选列出来再确认一次，不要猜。

如果 harness 有结构化提问的能力（比如 Claude Code 的 AskUserQuestion），清单较短时可以用它，选项标题用视频标题。清单长的时候直接给表格更好读。

用户说「都要」而条目超过 5 个，先提醒一句这要跑一阵，问他确认。

### 3. 取字幕

对每个选中的视频跑：

```bash
"$SKILL/scripts/transcript.sh" "<VIDEO_ID>" --format ts > <工作目录>/<VIDEO_ID>.ts.txt
```

工作目录用 scratchpad，不要写进用户的仓库。

`transcript.sh` 是 `youtube-transcript-api` skill 的转发壳，自己会找到那个 skill。视频有中文字幕的话加 `--lang zh-Hans,zh,en` 优先取中文。

**取不到字幕的视频照实说，别用标题硬编内容。** 常见两种：字幕被关（`TranscriptsDisabled`），或者机房 IP 被封（`RequestBlocked`）。前者是这个视频的问题，跳过它继续处理别的；后者是环境问题，会影响全部，直接告诉用户并停下。

标题、频道、时长第 1 步的清单里已经有了，不用再抓一次。

### 4. 写摘要

**动笔前把 `.ts.txt` 完整读完。** 只读开头结尾写出来的摘要，看着像回事，实际不携带信息，正好是这个 skill 要避免的东西。

每个视频一段，格式固定：

```
### <序号>. <标题>

<频道> · <时长> · https://www.youtube.com/watch?v=<ID>

**一句话**：这视频在讲什么，给一个判断，不是内容清单。

**要点**

- [12:30] 一条要点，带时间码，讲者真说过的
- [18:05] 有硬数字就带上数字

**这些段落值得单独点开**

- [24:10] 为什么这一段值得看
```

写的时候：

- **要点 3 到 6 条**，每条挂时间码。时间码是给用户跳回去核对用的，必须指向那条要点真正开始的位置。
- **一句话那栏给判断，不给目录。**「讨论了硬件、创业和职业建议」是目录；「他认为算力瓶颈已经从训练转移到推理，后面所有建议都是从这个判断推出来的」才是判断。
- **有数字就留数字。** 倍数、百分比、年份、成本，这些是用户判断值不值得看的主要依据。
- **「值得单独点开」这栏可以没有。** 整个视频都平均的时候就不写，硬凑等于没说。
- 自动字幕的音近错误（人名、机构名、缩写）按上下文还原，还原了就在那条要点后面用括号标一下原始转写。没把握就保持原样并注明不确定。

### 5. 收尾

摘要给完，提一句下一步可以做什么：某个视频想要能替代观看的长文，就转 `youtube-reading-page`。**只提一句，不要自动去跑**——那个 skill 一个视频要跑很久。

## 三条不可让步的规则

**不新增事实。** 摘要里每一句都必须能在字幕里找到出处。不要补背景知识，不要从标题推测内容，不要把「他大概是这个意思」写成他说了。

**取不到就说取不到。** 没有字幕的视频，如实报告，绝不根据标题和频道编一份摘要出来。这是这个 skill 最容易出事的地方，因为编出来的东西看着完全合理。

**不替用户挑。** 第 2 步必须真的停下来等。用户要的是自己挑，不是让你挑完通知他。

## 语言

清单和摘要默认跟用户说话的语言走。视频是英文的，摘要用中文写，但专有名词保留英文原文。
