## 长度：为什么是下限而不是配额

每个主题小节和每个 framework 大致 500–900 字。这个数字是**下限**，作用是逼出细节密度——低于它几乎必然意味着你把内容压扁了。

但它不是配额，两件事必须分清：

- **合规的加长**：补上转录里本来就有的因果链、前置条件、具体数字、嘉宾自己加的限定语和反例。
- **不合规的加长**：同义反复、把一句话拆成三句说、加转折词凑长度、写"这一点非常重要"这类不携带信息的句子。

判断方法：删掉某一句，读者会不会少知道一件事？不会，就该删。

**永远不要在输出里提到字数要求。** 读者看到的是一篇文章，不是一份交付清单。

## 一个小节怎么写到位

先看反例。转录里说了这么一串：2013 年语音模型错误率减半 → 但计算量大得多 → 担心用得多了扛不住 → 算出每人每天三分钟就要机群翻倍 → 所以做了 TPU。

压扁的写法是："Jeff Dean 通过餐巾纸计算发现语音识别成本过高，因此开发了 TPU。" 一句话，全部要点都"提到"了，但读者什么也没得到——他不知道为什么质量提升会变成成本危机，不知道那个三分钟假设从哪来，不知道"翻倍"这个量级为什么否定了增量优化路线。

写到位的做法是**把因果链的每一环都还原成读者能自己推一遍的形式**：

- **起点是什么状态**——不只是事件，还有当时的约束和已知条件。
- **中间那一跳是什么**——这里通常藏着讲者真正的洞察。上例里是"质量提升本身会制造需求，需求会制造成本危机"这个反直觉的转折。这一跳最容易在压缩中丢失，而它恰恰是整段最有价值的部分。
- **数字如何进入**——那个假设是怎么设的，算出来是多少，这个量级意味着什么。
- **结论为什么是这个而不是别的**——为什么是换路线而不是优化实现。

其它有用的手段：

- **段落要短，逻辑要分层。** 一段讲一件事。并列的要点用 bullet 拆开——三个理由写成三个 bullet，比塞进一个长段落好读得多。
- **保留讲者自己加的限定和反悔。** "我不是说我们应该真去做这个"、"这类实验往往不成立"——这些是讲者思维方式的一部分，删掉会让他显得比实际更武断。
- **保留对话里的往返。** 主持人的追问经常是文章的转折点，因为它逼出了嘉宾没打算主动讲的东西。可以写成"被追问 X 时，他的回答是 Y"。
- **点出呼应。** 同一个概念在视频前后两处出现时，明确写出来（"这与前面 X 那一节是同一条线索"）。观看时人靠记忆建立这种连接，阅读时你得替读者建立。

## Overview 怎么写

一段话（可以两段），点明**核心论题与结论**，不是内容清单。

- 差："视频讨论了硬件、agent、创业选题和职业建议。"——这是目录，不是论题。
- 好：先给出贯穿全场的那条主线（通常是一个判断或一组取舍），再用一句串起各个主题如何支撑它。

如果视频本身没有单一主线（松散访谈常见），如实说明它是多主题的，然后给出主题之间实际存在的关联，不要硬凑一个不存在的中心思想。

## 标题和 TL;DR

这两样决定别人会不会点进来、会不会读下去，所以放在最前面，但要最后写。

**标题**用全场最反直觉的一两个**具体做法**当钩子，加上最有分量的那个数字，讲者和机构放在末尾。

- 差："<讲者> 谈 <主题>"、"从 <数字> 到 <比喻>：如何做好 <主题>"。这是在复述主题，读者看不出有什么是他不知道的。
- 好："<最硬的数字>：<反直觉做法 1>，<反直觉做法 2>｜<讲者> @ <机构>"。做法要具体到读者能想象出画面，而且都是讲者原话里明确说过的。
- 钩子必须是事实。不要用"她做的第一件事是……"这类原话里没有的顺序，也不要用问句和感叹号制造悬念。

**TL;DR** 放在标题之后、元数据之前，写 3–5 条"反共识"：和读者的常见做法或直觉相反的判断。

- 每条的格式：加粗的一句判断，后面一两句讲者给的理由，最后是时间码。
- 选条标准是"读者原来会怎么做，讲者说该反过来"。普通结论（"验证很重要"）不算反共识，不要凑数。
- 开头一句交代讲者是谁、那个最硬的数字，以及讲者自己怎么看这个数字。
- 写完逐条对回原话。TL;DR 是全文最容易说满的地方：数字不要放大，限定词不要加，推断不要写成原话。

## 插图

演讲类视频的幻灯片是讲者自己画好的图，信息密度高、可信，优先用截图，不要自己重画。截图流程和脚本见 SKILL.md 第 5b 步。

**值得放的**：讲者自己画的图示、流程图、层级列表、带数字的图表，以及讲者反复回来指的那一张（通常是"如果只记住一件事"的那页）。一小时的内容 6–8 张就够了。

**不放的**：

- 只有标题的封面页、和另一张信息重复的页。
- 带内部聊天、邮件、人名的产品截图。看不清，也不该传播。
- 讲者的摄像头画面、字幕条。

**位置和说明**：插在讲到这张图的那段话后面。图注一句话讲清这张图在说什么，末尾写"（视频 mm:ss 幻灯片）"，方便读者跳回原片。

**幻灯片也是证据**。截图时顺手读一遍上面的字，它经常能纠正转写和你自己的归纳。常见的情况是：名字的正确拼写、讲者列表的真实条数（口头讲解时常把几条合在一起说）、口头没说出来的数字。发现不一致时，以幻灯片为准并改正文。

## 处理转录错误

自动生成的字幕必然有音近错误，尤其是人名、机构名、缩写和专业术语。真实例子（英文自动字幕）：

| 转录原文 | 实际 | 类型 |
|---|---|---|
| `Europe` | NeurIPS | 会议名 |
| `HPM` | HBM | 缩写 |
| `Oral Fin` | Oriol Vinyals | 人名 |
| `read Solomon` | Reed-Solomon | 术语 |
| `map produce` | MapReduce | 术语 |
| `subpros` | subproblems | 词被截断 |

处理方式：

1. **按上下文还原**——只在你有把握的时候还原。判据是这个词在该语境下有唯一合理解释。
2. **正文直接写正确的词，不加标注**——不要逐处放说明块、括号注释（"字幕此处为……"），也不要在文末附对照表。这些东西读者反馈"对读者没啥帮助"，只会打断阅读。还原依据记在工作目录里，自查时用。
3. **开头声明一次**——在元数据附近用一句话说明本文基于自动字幕，专有名词经过音频核对。
4. **没把握就换说法**——定不下来的名字不写进正文，改用不依赖它的描述（用它的性质或作用来指代，而不是一个猜出来的名字）。猜一个像样的词比留下明显的错误更危险，因为读者无法察觉。

可核对性靠每节的时间码保证：读者想验证，拿时间码跳回原片即可。

## 引用原话

值得直接引用的是那些**改写会损失力量**的句子——判断、反直觉的表述、有记忆点的比喻。普通陈述句改写成中文即可，不要为了显得有据而堆引用。

引用时：

- 保留英文原文，下面给中文翻译。
- 附上时间码或说话人，让读者能核对。
- 一节里通常 0–2 处。超过就说明你在用引用代替自己的组织工作。

## 抽 framework：这部分最容易写砸

**失败模式是把小节内容换个说法再写一遍。** 如果第四部分读起来像前面小节的复述，它就没有存在价值。

framework 的价值在于**可迁移**——读者能把它用在视频没讨论过的场景上。所以每个 framework 应该：

1. **先点明它解决什么问题**——一句话，写成读者可能遇到的处境，而不是视频里的处境。
2. **给出执行步骤或判据**——编号步骤、判断标准、读数规则。这部分要具体到能照着做。
3. **保留视频里的原始素材作为例证**，但**位置换了**：在主题小节里，例子是主体；在 framework 里，例子是对抽象结构的验证。
4. **写出失败模式**——这个框架在什么情况下会被用错。这一条最有价值，也最常被漏掉。视频里讲者经常主动给出警告（"但我要提醒的是…"），那些就是失败模式的原始素材。

素材来源的优先级：

- 讲者明确给出的方法、判据、步骤——最直接。
- 讲者反复使用的思维动作。同一个动词或同一种转折在全场出现多次时，那通常是他方法论的核心，即使他自己没有命名它。
- 多个分散案例背后的共同结构。这类抽象最有价值，但要确保是内容里真实存在的结构，不是你套上去的模板。

数量上，一小时的内容通常能抽出 3–6 个。**宁少勿凑**——凑出来的 framework 会稀释真正有价值的那几个。

## 页面设计

有 `artifact-design` 这类设计 skill 就先调它定基调，没有就直接照下面来。以下是这类长文特有的经验：

**有用的结构**

- **时间码栏**——每个小节挂起始时间码。宽屏时放进左侧留白栏，窄屏时放在标题上方。它同时承担导航和可核对性两个功能。
- **硬数字带**——把全片最有分量的 4–6 个数字抽出来做成一个视觉区块（倍数、比例、成本）。这类内容的说服力集中在数字上，把它们聚起来给读者一个抓手。数字不够多的视频（偏理念型）就不要硬做。
- **转录说明块**——和正文区分开的小块，用于标注还原过的转写错误。
- **引用块**——原文加译文，带出处。

**要避开的**

- 给非序列内容加 01/02/03 编号。时间码已经编码了顺序，再叠一层编号是装饰而非信息。
- AI 生成感强的默认审美：暖米色背景配衬线标题配陶土色点缀、近黑背景配单一荧光绿、紫蓝渐变 hero、全局圆角卡片配左侧色条。
- 巨大的 hero 区。这是一篇文章，读者是来读的，不是来看落地页的。

**必须做对的**

- 亮色和暗色两套主题都要走 token 定义，`body` 必须显式设背景色。
- 中文正文行高给足（1.8 左右），阅读区宽度控制在 65–70 字符。
- 宽内容（表格、代码）各自 `overflow-x: auto`，页面本身不能横向滚动。

## 完成前自查

- 每个小节是否都能让读者不看视频就理解该主题？
- 有没有哪一句是我从自己的知识里补的，而不是视频里的？
- 转写错误是否都在正文里改对了？正文里是否已经没有逐处的转录说明块和对照表？没把握的名字是否换成了不依赖它的说法？
- 标题的钩子和 TL;DR 的每一条，是否都能对回原话？有没有加顺序、放大数字、加限定词？
- 每张截图是否都跑过 `slides.py check`，标题、边框、脚注完整，没有摄像头和字幕残留？
- framework 是不是小节的复述？有没有写失败模式？
- 主持人 / 嘉宾的姓名是不是有出处？
- 输出里有没有泄漏"字数要求""按要求"这类交付语言？
- 时间码是否准确指向该主题的起始位置（读者会拿它跳回去核对）？
